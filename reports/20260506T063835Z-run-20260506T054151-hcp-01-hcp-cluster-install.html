Events & findings

  • CLUSTERS-MGMT-403 on machine pool and identity provider updates during Terraform phase 2 after the cluster was already ready in OCM. Scripted retries (5×) exhausted; a follow-up terraform apply from clusters/hcp/terraform succeeded in ~47s.
  • make create-hcp exit code: the log shows make: *** [create-hcp] Error 1 while a background wait on the tee side of the pipeline could report 0 — treat the log line as authoritative.
  • oc login: harness wait_oc_login_success uses user cluster-admin; this HCP stack provisions htpasswd user admin. Validation used admin + CLUSTER_ADMIN_PASSWORD after Terraform applied the IDP.
  • openshift-machine-api events: oc get events returned no resources on this cluster at observation time (HCP worker lifecycle may not surface the same event stream as Classic).

Narrative

The cluster reached a usable OCM ready state quickly (~21m from benchmark start by phase-1 inference), consistent with HCP expectations. A transient OCM 403 race during Terraform phase 2 extended wall time until a second apply completed IDP and machine pool metadata. Subsequent oc checks confirmed three workers Ready and ClusterOperators Available within seconds of a successful admin login. Consider raising ROSA_HCP_TERRAFORM_403_MAX_RETRIES / sleep or ROSA_HCP_POST_CLUSTER_SLEEP_SEC if this pattern repeats.
