Events & findings

  • Bug found & fixed: clusters/common.sh:wait_oc_login_success used --insecure-skip-tls-verify=false, which triggers an interactive "Use insecure connections? (y/n):" prompt when the API server presents a self-signed cert. This blocked unattended automation. Fixed to --insecure-skip-tls-verify=true.
  • ROSA version pinned to 4.19.30 by the create script (overrides classic.env's ROSA_VERSION=4.21.12). Check clusters/classic/create.sh for the pin if you want a different version.
  • Multi-AZ topology with autoscaling workers (3–9 nodes) in us-east-1.
  • All 32 ClusterOperators reached Available=True within the expected timeframe.
  • Warning: ROSA CLI 1.2.60 is not the latest (1.2.62). Update with rosa download.
  • Warning: More than one Installer role found in account — harness selected ManagedOpenShift-Installer-Role automatically.

Narrative

The Classic cluster provisioned in 47m 38s — solidly within the 45–65 minute expected range and near the fast end. OCM reached ready at 45m 42s, which is the dominant phase and typical for ROSA Classic STS multi-AZ. The post-ready phases were exceptionally fast: oc login succeeded in 1m 34s, all workers were confirmed Ready just 4s later (they were already up), and all 32 ClusterOperators became Available 18s after that. The cluster is healthy and ready for test 02.

One automation issue was identified and repaired: the oc login retry loop in clusters/common.sh used --insecure-skip-tls-verify=false, which on a fresh cluster (whose API cert is not yet CA-signed in the client's trust store) causes the OpenShift CLI to prompt interactively for confirmation. This blocked the automated benchmark until a human sent "y". The flag has been corrected to --insecure-skip-tls-verify=true for all future runs.
