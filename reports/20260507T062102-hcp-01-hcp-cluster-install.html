Events & findings

  • Bug 1 — CLUSTERS-MGMT-400: min_replicas not a multiple of subnets. The upstream module commit 07b724e ("update to support hcp autoscaling in provider") passed per-pool default_min_replicas_per_pool = 1 to rhcs_cluster_rosa_hcp.min_replicas, but OCM interprets that attribute as a cluster-total. For a 3-AZ cluster the total must be a multiple of 3 (one per subnet). Fixed in d6ae385: introduced hcp_max_replicas local and changed the cluster resource to use hcp_replicas (= per_pool × num_azs = 3) and hcp_max_replicas (= 9).
  • Bug 2 — EFS security group timing race. The first make reconcile-hcp failed because data.aws_security_groups.cluster_default[0].ids was empty — the ROSA-managed cluster SG is not immediately visible in AWS after the cluster resource is created. A second reconcile ~2 minutes later found the SG and completed the EFS mount target configuration in ~90 s.
  • Zero 403 errors. With min_replicas = 3 / max_replicas = 9 set at cluster creation, ROSA provisioned the three default pools (workers-0/1/2) with autoscaling already active. The rhcs_hcp_machine_pool updates were no-ops (min=1/max=3 per pool matched), completing in 2–5 s with no forbidden errors.
  • Machine pools ready concurrent with OCM ready. The provider's wait_for_std_compute_nodes_complete = true flag caused it to wait for all 3 workers to be Ready before returning, so hcp.machine_pools_ready is only 35 s after hcp.cluster_ready — effectively simultaneous.
  • 21 ClusterOperators all healthy within 8 minutes of OCM ready — well within the expected 2–10 min range.

Recovery narrative

Partial run — two bug-fix iterations

This run benchmarked the first exercise of the new single-shot apply path with the autoscaling-at-creation upstream module fix. Two bugs were discovered and fixed in sequence:

  1. Wrong min/max semantics: upstream commit 07b724e used per-pool values where OCM expects cluster-totals. Fixed in d6ae385, pushed, and Terraform re-initialized (~7 min overhead).
  2. EFS SG race: cluster SG not yet visible in AWS immediately after creation. Fixed by running a second make reconcile-hcp ~2 min later.

A clean repeat run with module d6ae385 should complete end-to-end in ~20–22 minutes (OCM ready ~15–18 min, workers and operators within 8 min after that), with no 403 retries.

Narrative

A new hcp-bench ROSA HCP cluster was provisioned as the first end-to-end test of the single-shot Terraform apply path combined with the upstream autoscaling-at-creation fix. The initial apply failed with a CLUSTERS-MGMT-400 because the upstream module's first attempt at setting cluster-level autoscaling used per-pool replica counts where OCM expects cluster totals. After correcting the module (introducing hcp_max_replicas = per_pool × num_azs) and re-initializing, a make reconcile-hcp provisioned the cluster in 10m 17s with zero 403 errors — the three default machine pools applied in under 5 s each. A second reconcile was needed to attach EFS mount targets (AWS SG propagation race), but that completed cleanly in ~2 minutes. oc login succeeded immediately, all 3 workers were Ready, and all 21 ClusterOperators reached Available=True within 27 minutes of the original benchmark start (including ~7 minutes of bug-fix time).
