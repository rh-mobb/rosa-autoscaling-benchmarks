Events & findings

  • First make create-classic submitted the cluster but the client was stopped mid-flight; operator IAM roles and OIDC provider were never created. OCM stayed in waiting with “Operator Role(s) not found”.
  • Recovery: rosa create operator-roles --cluster=classic-bench --mode=auto --yes then rosa create oidc-provider --cluster=classic-bench --mode=auto --yes. Cluster moved to pending, then installing, then ready.
  • clusters/classic/resume-install-wait.sh (nohup) completed post-ready checks; oc wait for workers reported a timeout but all labeled worker nodes were Ready on re-check after fresh login.
  • Re-login from this host required --insecure-skip-tls-verify=true until local trust store matched the API cert; use a normal login once CA is trusted.
Interrupted create / seeded timing

classic.create_submitted was written with record-event.py after the fact (68s from benchmark start, aligned to log timestamps) because emit_timing never ran before the signal. classic.manual_operator_roles_and_oidc captures wall time from benchmark start to the manual IAM step for narrative only — it overlaps the first failed wait window and is not a linear phase. For a apples-to-apples Classic install benchmark, destroy the cluster and rerun make create-classic under nohup or a session that will not send SIGTERM mid-create, and complete operator roles + OIDC immediately after rosa create cluster if your CLI ordering matches the ROSA docs.

Narrative

Post-recovery segments match expectations: about 22 minutes from OCM ready to working oc login, then tens of seconds for workers and operators once the API was stable. The headline ~163m total is dominated by the initial stuck waiting state and manual recovery, not ROSA install performance. After recovery, multi-AZ workers (three workers plus infra) reported Ready.
