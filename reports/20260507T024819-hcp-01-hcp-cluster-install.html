Events & findings

  • Phase 2 CLUSTERS-MGMT-403: machine pools and htpasswd identity provider updates were rejected repeatedly after the hosted control-plane cluster was already ready; scripted retries slept ~22 minutes total (hcp.ocm403_retry_sleep).
  • Reconcile caveat: an immediate make reconcile-hcp without BENCHMARK_RUN_ID tried to mutate cluster tags.BenchmarkRun from the run-scoped tag to literal manual, which RHCS rejected (tags cannot be changed). Re-running reconcile with export BENCHMARK_RUN_ID=20260507T024819-hcp regenerated matching tfvars and apply finished in ~45 s.
  • openshift-machine-api: oc get events -n openshift-machine-api returned no rows at observation time on this HCP cluster (consistent with reduced machine-API surfaced events vs Classic).
Partial run / recovery

Interpret ~19 min to Terraform phase 1 / OCM-ready proxy as the core install signal. Wall-clock login and totals are elongated by transient OCM 403 during phase 2 plus human/tooling reconcile. For frictionless benchmarks, reuse BENCHMARK_RUN_ID on any scripted make reconcile-hcp; consider tuning ROSA_HCP_POST_CLUSTER_SLEEP_SEC, ROSA_HCP_TERRAFORM_403_MAX_RETRIES, and ROSA_HCP_TERRAFORM_403_RETRY_SLEEP_SEC in hcp.env if the pattern repeats.

Narrative

A new hcp-bench ROSA HCP cluster was provisioned with Terraform phased apply. Phase 1 completed in about 19 minutes, after which phase 2 stumbled on intermittent OCM forbidden responses while attaching default machine pools and the admin IDP. The cluster nevertheless appeared ready in OCM mid-run with three workers. Completing reconcile with the benchmark run ID restored tag consistency so Terraform succeeded, then oc login as admin, worker Ready, and ClusterOperator Available checks finished within seconds.
