Events & findings

  • TLS prompt on oc login: The cluster API endpoint uses a certificate signed by an unknown authority. The create script's oc login invocation did not pass --insecure-skip-tls-verify, causing an interactive prompt ("Use insecure connections? y/n"). The retry loop eventually succeeded after manual confirmation; this added ~3 min to the post-ready phase.
  • ROSA version override: classic.env specifies ROSA_VERSION=4.21.12 but the create script pinned 4.19.30. Confirm intended version for future runs.
  • 3 worker nodes (m5.xlarge, multi-AZ us-east-1) all reported Ready within 4 seconds of successful login — essentially immediate.
  • All 32 ClusterOperators reported Available=True within 16 seconds of workers being Ready.

Narrative

Total install time of 60m 49s is slightly above the expected 45–65 min window (within the 1.5× threshold of 97.5 min). The bulk of time (57m 19s) was spent waiting for OCM to report the cluster ready — the typical control-plane provisioning phase for Classic. Post-ready work was fast: login took 3m 9s (partly due to the TLS prompt retry), and workers plus operators were ready in under 30 seconds from there. No anomalies in openshift-machine-api events. The cluster is operationally healthy and ready for test 02 (machine pool benchmarks).
