Events & findings

  • Terraform race on EFS: After rhcs_cluster_rosa_hcp completed (~10 min), data.aws_security_groups.cluster_default returned an empty ids list, so ingress rules and EFS mount targets failed with Invalid index. Running make reconcile-hcp after the SG existed succeeded (~2 min apply).
  • Reconcile tags: The first reconcile attempt without BENCHMARK_RUN_ID tried to change cluster tag BenchmarkRun from this run ID to manual; RHCS rejected it. Re-run with export BENCHMARK_RUN_ID=20260507T232347-hcp before make reconcile-hcp.
  • Worker wait: An immediate oc wait node -l node-role.kubernetes.io/worker after login initially saw no nodes (API lag); a later wait succeeded. hcp.machine_pools_ready uses an approximate end timestamp between login and the long operator wait.
  • openshift-machine-api: On this HCP guest, oc get events -n openshift-machine-api often shows few or no rows versus Classic (expected for hosted control planes).
Recovery path used

make create-hcp → failed apply → export BENCHMARK_RUN_ID=20260507T232347-hcp && make reconcile-hcp → manual emit_timing / oc milestones for cluster_ready, login, pools, operators, and record-event.py record for reconcile. Cluster is left running for tests 02–09.

Narrative

A new hcp-bench ROSA HCP cluster was provisioned with the repo’s single-shot Terraform apply. The control plane and default node pools were created in OCM, but the module’s EFS step queried AWS default security groups before they were observable, aborting the apply. Terraform reconcile with the original BENCHMARK_RUN_ID completed the AWS side; then oc login as admin, worker readiness, and ClusterOperator availability checks finished successfully. End-to-end wall clock from harness start through operators was about 24 minutes, with roughly 13 minutes in the failing first apply and 2 minutes in the successful reconcile apply.
