Events & findings

From install log and timing labels.

  • OCM install transitioned waiting → pending → installing; cluster reached OCM ready after ~47m from benchmark start (within the skill’s typical 45–65m total band when including post-ready checks).
  • API availability after OCM ready: ~10.5m elapsed between classic.cluster_ready and a successful oc login, consistent with the skill’s “OCM ready → oc login ~2–10 min” guidance at the high end.
  • Workers: six worker nodes reported Ready in quick succession once the API accepted logins; incremental time from login to classic.machine_pools_ready was ~5s.
  • ClusterOperators: oc wait completed within ~1s of workers ready (operators already satisfied or nearly so).
  • Provisioning lead-in (classic.create_submitted): ~1m19s for quota check, rosa create cluster --mode auto, operator IAM roles, and OIDC provider creation before the script began polling for OCM state.

Narrative

This run shows a healthy ROSA Classic multi-AZ install: most wall clock is OCM moving the cluster to ready. The dominant post-ready delay was waiting for the public API endpoint to accept authentication after OCM declared readiness (~10.5m). Subsequent milestones (all workers Ready, all operators Available) stacked within seconds—expected once control plane and workers are fully registered. Total script-derived install time 57m 55s is within the benchmark skill’s 45–65 min Classic reference for end-to-end harness completion.
